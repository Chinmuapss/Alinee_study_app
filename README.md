# iBantay — A Mobile Application for Real-Time Community Incident Reporting

iBantay is a Flutter application for submitting community incident reports with real GPS coordinates to Supabase. The same project serves a mobile reporter experience and a browser-based responder dashboard. It is a **school research prototype**, not a connection to public emergency services.

## What is included

- Supabase email/password registration, login, logout, and persisted sessions.
- Incident reporting for robbery, theft, shooting, fire, accident, medical, and other emergencies; the emergency route requires explicit confirmation.
- Device GPS permission and high-accuracy coordinate collection, optional camera attachment, graceful user-facing location and network failures.
- Report history and current workflow status for each reporter.
- Role-restricted responder dashboard: counts, report details, GPS map link, and safe status workflow updates.
- `created_at`, `received_at`, and `location_accuracy` measurements. These are real submitted/received timestamps and device-reported accuracy—no results are fabricated.
- Paste-ready Supabase schema, indexes, status audit history, RLS, and Storage policies.

## 1. Prerequisites and install

Install the current [Flutter SDK](https://docs.flutter.dev/get-started/install), Android Studio for Android, and Xcode on macOS for iOS. Then run:

```bash
flutter pub get
cp .env.example .env
```

> `.env` is intentionally ignored by Git. Never use a Supabase service-role key in this application.

## 2. Configure Supabase

1. Create a Supabase project and copy the **Project URL** and browser-safe **anon key** from **Project Settings → API** into `.env`.
2. In **SQL Editor**, paste and run [`supabase/schema.sql`](supabase/schema.sql). It creates profiles, reports, status history, indexes, report IDs such as `IB-000001`, RLS, and the private photo bucket policies.
3. In **Authentication → URL Configuration**, add your web deployment URL and any development redirect URLs.
4. Register a responder normally, then promote that account in SQL using the commented `update public.profiles` command at the bottom of the schema. Only responders/admins can see all reports or change statuses.

The database sets `received_at` at insertion. Alert delivery time is calculated as `received_at - created_at`; researchers can inspect it in report details and dashboard. To calculate external location error, compare the stored latitude/longitude with the known reference coordinates in metres. iBantay does not claim GPS is perfectly accurate.

## 3. Run the reporter app

Connect an Android/iOS device (location must be enabled), then:

```bash
flutter run
```

Sign up, choose an incident card, verify the automatically obtained coordinates, add an optional photo, and submit. `EMERGENCY REPORT` opens the same flow with an additional confirmation before any database write.

## 4. Run the responder dashboard (web)

Use a responder/admin account:

```bash
flutter run -d chrome
```

Open the navigation drawer and select **Responder Dashboard**. It presents actual database totals and delivery/GPS data. Each report opens a map location through OpenStreetMap, so no map API key is needed. If you replace this with Google Maps later, inject its API key through a build/deployment environment configuration—never source code.

## 5. Deployment

```bash
# Android
flutter build apk --dart-define-from-file=.env
flutter build appbundle --dart-define-from-file=.env

# Web (deploy build/web to your HTTPS host, then add that URL in Supabase Auth)
flutter build web

# iOS (on macOS)
flutter build ios
open ios/Runner.xcworkspace
```

For Android, complete your application ID/signing configuration generated by `flutter create .` before publishing. For iOS, set the signing team, bundle identifier, privacy details, and App Store Connect metadata in Xcode. GPS and camera permission texts are included in the platform files. Production web deployment should be HTTPS so browser geolocation works.

## Project layout

`lib/services` contains authentication, Supabase, GPS, and report/database operations; `lib/screens` contains reporter flows; `lib/dashboard` is the responder web workflow; `lib/widgets` provides reusable high-contrast components; and `supabase/schema.sql` is the backend contract. Run `flutter create .` once on a machine with Flutter if platform scaffolding (Gradle/Xcode project files) has not yet been generated.
